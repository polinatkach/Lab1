# Лабораторная работа № 1 — объектно-ориентированная модель ресторана

## О работе

Учебный проект на Python, моделирующий предметную область ресторана с использованием объектно-ориентированного программирования. Программа демонстрирует классы и связи между сущностями, базовые операции управления данными (CRUD), собственные исключения и сериализацию в JSON и XML.

Тема работы: «ООП в Python. Обработка исключительных ситуаций. Форматы XML и JSON».

## Основные возможности

- 13 классов предметной области: категория блюд, меню, зал, столик, клиент, официант, смена, продукт, блюдо, состав блюда, бронь, заказ и позиция заказа. Все они наследуются от общего класса `Entity`;
- главный класс `Restaurant`, который хранит все списки объектов и выполняет операции добавления, поиска, изменения и удаления;
- проверка входных данных (пустые строки, ID, числа, даты и время, статусы);
- контроль связей: нельзя добавить объект со ссылкой на несуществующий зал, меню, клиента и т. д.;
- бизнес-правила ресторана:
  - номер столика уникален в пределах зала;
  - гостей не может быть больше, чем мест за столиком;
  - один столик нельзя забронировать дважды на одно и то же время;
  - позиции закрытого (оплаченного или отменённого) заказа менять нельзя;
  - нельзя удалить объект, на который есть ссылки (клиента с бронями, официанта с заказами, блюдо в заказах, бронь с заказом);
- подсчёт суммы заказа и список блюд меню;
- иерархия исключений: `RestaurantError` → `EntityNotFoundError`, `DuplicateEntityError`, `ValidationError`, `StorageError`;
- сохранение и загрузка данных в форматах JSON и XML;
- демонстрационный набор данных;
- автоматические тесты (`unittest`);
- UML-диаграмма классов в графическом (PNG) и векторном (SVG) форматах.

Все данные в демонстрационном наборе учебные. Проект не предназначен для хранения реальных персональных данных и не является системой учёта для реального заведения.

- Python 3.10 или новее (для `ET.indent` нужен Python 3.9+);

## Запуск

Перейдите в каталог `Laba1_restaurant` и выполните:

```bash
python main.py
```

Без параметров программа загружает `data/restaurant.json` и выводит сводку; если файла ещё нет, показываются демонстрационные данные.

Создание демонстрационных файлов JSON и XML в каталоге данных:

```bash
python main.py --demo
```

Указать другой каталог данных:

```bash
python main.py --demo --data ./my_data
```

Пример вывода:


```bash
python -m unittest -v test_restaurant
```

Результаты последней проверки приведены в `docs/TEST_RESULTS.txt`.

## Форматы данных

- **JSON** — корневой объект с полем `restaurant` и массивами объектов по типам (`categories`, `menus`, `halls`, `tables`, `customers`, `waiters`, `shifts`, `products`, `dishes`, `ingredients`, `reservations`, `orders`, `order_items`). Связи между объектами задаются числовыми ID.
- **XML** — корневой элемент `<restaurant name="...">` с группами `<halls>`, `<tables>`, `<dishes>` и т. д.; поля сущностей — вложенные элементы. При загрузке числовые поля приводятся к `int` и `float`, после чего данные проходят те же проверки, что и при создании объектов.

Методы `save_json` / `load_json` и `save_xml` / `load_xml` входят в класс `Restaurant`.

## UML и отчёт

Диаграмма классов (`uml/uml_classes.png`, `uml/uml_classes.svg`) построена по коду `main.py`: показаны класс `Restaurant`, базовый класс `Entity`, 13 классов-сущностей со связями по ID (1 : 0..*), функции проверки данных, константы статусов и иерархия исключений. SVG-файл можно открыть и отредактировать в Inkscape или draw.io, либо изменить `uml/gen_uml.py` и запустить его заново:

```bash
cd uml
python gen_uml.py
```

Отчёт о выполнении работы — `docs/report.docx`.
